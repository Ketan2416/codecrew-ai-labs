03

General notes

How we work

  1. Specification before code.

    Every engagement starts with a written document: what is being built, what it is not, and how we will know it works. If we cannot agree on that document, the project is not ready to start.

  2. You talk to the engineer.

    No account layer. The people writing the code are the people in your calls and in your channel, for the length of the project.

  3. Agents need evaluation, not demos.

    A model that looks impressive in a screen recording is not a system. We ship agents with test cases, logging and failure handling, so you can see what they do when nobody is watching.

  4. We maintain what we build.

    Handover includes documentation and access, and we stay reachable afterwards. Software that nobody owns stops working.
